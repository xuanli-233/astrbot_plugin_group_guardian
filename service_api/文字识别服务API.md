# 文字识别服务 API（RapidOCR）

图片文字识别（OCR）：上传一张图片，返回图里的文字。插件把识别出的文字按规则组的关键词过滤。

本文只写插件用到的部分；完整协议见服务自己的 `API.md`（部署目录 `deploy-api\rapidocr-service`）。

| 项目 | 值 |
| --- | --- |
| 默认地址 | `http://127.0.0.1:8110`（插件配置 `local_ocr_service_url`，留空就用这个） |
| 接口 | `POST /v1/ocr`、`GET /health`、`GET /ready` |
| 鉴权 | 无（服务只监听本机回环，不要暴露到公网） |
| 并发 | 单进程、单 worker 串行识别；等待队列 8，满了返回 `503 queue_full` |
| 模型 | PP-OCRv6 tiny（检测 + 识别），CPU 推理；900×520 的图约 0.2 秒 |

## 1. `POST /v1/ocr`

### 1.1 请求

`multipart/form-data`：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `file` | 是 | 图片文件 |
| `detail` | 否 | `false`（默认）只返回文字；`true` 额外返回每行的置信度和四点框。插件固定传 `false` |

```bash
curl -X POST "http://127.0.0.1:8110/v1/ocr" -F "file=@image.png" -F "detail=false"
```

### 1.2 成功响应（HTTP 200）

```json
{
  "text": "RapidOCR 文字识别服务\n邀请你一起超值拼团\n0元拼团·无需支付",
  "texts": ["RapidOCR 文字识别服务", "邀请你一起超值拼团", "0元拼团·无需支付"],
  "count": 3,
  "timing_ms": {"queue": 0.027, "ocr": 240.122}
}
```

图里没有文字也是 HTTP 200，`count` 为 0。

### 1.3 其它状态码与插件的处理

| 状态码 | 含义 | 插件怎么处理 |
| --- | --- | --- |
| 400 | 缺文件、空文件、`detail` 非法 | 当作服务异常，放行并记日志 |
| 413 | 文件或像素超过限制 | 跳过这张图（放行） |
| 415 | 格式不支持（如 GIF） | 跳过这张图（放行）；GIF 插件根本不发 |
| 422 | 图片损坏 | 跳过这张图（放行） |
| 503 `queue_full` | 等待队列满，带 `Retry-After: 1` | 按 `Retry-After` 等一会重试，最多重试 2 次，每次最多等 3 秒；还是满就放行 |
| 连不上 / 超时 | — | 放行，日志里同一原因 10 分钟只写一次 |

「放行」= 这张图当作没有文字，不撤回。实时日志里会写明原因。

## 2. `GET /health`、`GET /ready`

进程存活 / 模型就绪检查，正常时返回 HTTP 200。管理页面「识别服务与转发群 → 图片文字识别 → 测试连接」会依次请求这两个接口。

## 3. 插件侧的限制

- 同时最多向服务发 4 个请求（服务队列是 8，留出余量）；每条消息最多识别 4 张图。
- 每张图的超时是 `local_ocr_timeout`（默认 10 秒，1-60）。
- 同一张图（按内容哈希）10 分钟内只识别一次，结果放在内存里，重启后清空。
- 下载图片沿用插件的受控下载：最大 5 MiB，拒绝内网地址。
